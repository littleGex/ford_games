# Ford House naughty elf Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From 1 to 24 December, P and Dude get a "Find the elf" job: find the elf (no marker), put his
mischief right, and take him back to his little door in the hall.

**Architecture:** Mirrors the Advent door. A small date store (`js/elf.js`, localStorage) says whether today's
elf has been found; `days.js` `tagsFor` adds a dynamic `elf` tag while he hasn't. The job lives in
`christmasJobs()` and is built from the day's scene (`pack/elfscenes.js`), chosen when the day is planned and
kept in the day's params. `systems/elf.js` puts the elf and the scene's props out at the start of a day.

**Tech Stack:** Plain ES modules, three.js, no build step. Tests: `npm run test:house` (node, stand-in three.js),
`npm run test:e2e` (Playwright).

**Spec:** `docs/superpowers/specs/2026-11-14-house-elf-design.md`

## Global Constraints

- Dates: 1-24 December only (the days with the `advent` tag), real dates via `holidays.js` `today()`.
- Once per real day: once found and taken home, he stays home until the next date, whatever "Start day N+1" does.
- One elf per device, shared by the players on it: when either P or Dude finishes the job it's gone for both.
- Never on Mum's or Dad's list.
- Switching "Christmas and the Advent calendars" off in settings switches the elf off.
- The find step has no floating marker.
- The elf is our own character: placeholder name `Pip` (one constant, `ELF_NAME`), red suit and hat, about 0.3 m.
- The same date gives the same scene on every device (no `Math.random`).
- localStorage key: `fordHouse.elf.v1`. Wrap every read and write in try/catch like `advent.js`.
- Comments and labels in the house's plain British English, as in the rest of `house/`.
- The existing play-through must pass unchanged.

## Review Focus

1. "Start day N+1" pressed again on the same date after finding him: no elf job, elf behind his door (Task 3).
2. P swaps to Dude halfway through the job: Dude carries on from the same step; once it's done, swapping back
   doesn't bring it back (Task 3).
3. Christmas switched off in settings on 3 December: no elf job, no door, no mess (Task 3).
4. The dragon switched off: the terrarium scene is never picked, and the day still gets a scene (Task 1, Task 4).
5. 3 December then 4 December: yesterday's mess is gone and only today's is out (Task 4).

### Task 1: The elf's date store and scene picking

**Files:**
- Create: `house/js/elf.js`
- Create: `tests/house/elf.mjs`
- Modify: `package.json` (`test:house` runs `node tests/house/elf.mjs` first)

**Interfaces:**
- Produces:
  - `ELF_KEY = 'fordHouse.elf.v1'`
  - `dateKey(date: Date) -> string` (`'YYYY-MM-DD'`, local date)
  - `pickScene(date: Date, scenes: Array<{id, needs?: string}>, isOn: (groupId) => boolean) -> string|null`:
    the scenes whose `needs` group is on, indexed by `(date.getDate() - 1) % allowed.length`; `null` if none.
  - `createElfLog({ now = today } = {}) -> { found(): boolean, markFound(): void, waiting(tags: string[]): boolean }`.
    `found()` is true when `dateKey(now())` is in the stored list; `waiting(tags)` is
    `tags.includes('advent') && !found()`. Stored as `{ found: ['2026-12-03', ...] }`, at most 40 entries kept.

### Task 2: The elf, his door and the scene system

**Files:**
- Create: `house/js/world/elf.js` (models), `house/js/systems/elf.js` (behaviour), `house/js/pack/elfscenes.js`
- Modify: `house/js/items.js` (the `elf` item), `house/js/main.js`
  (create `ctx.elfLog` and `ctx.elf` next to `ctx.advent` / `ctx.christmas`), `house/js/days/days.js`
  (`setupDay` calls `ctx.elf.reset(today.params)`; `binParams` adds `elfScene`)
- Test: `tests/house/playthrough.mjs` (inside the Christmas block)

**Interfaces:**
- Consumes: Task 1 `pickScene`, `createElfLog`.
- Produces:
  - `world/elf.js`: `makeElf(): THREE.Group` (sitting pose; about 0.3 m tall), `makeElfDoor(): THREE.Group`
    (about 0.12 × 0.2 m, on the skirting), `ELF_DOOR = { at: [x, z], place: [x, y, z] }` on a skirting board in
    the ground-floor hall (`world/rooms/flur.js` has its walls), reachable on foot. `systems/elf.js` adds the door
    to the ground floor. (The Advent calendars are on the living-room TV wall, not in the hall.)
  - `items.elf`: an item built by `makeElf`, home at `ELF_DOOR.place`, level 0, hidden at load.
  - `pack/elfscenes.js`: `ELF_NAME = 'Pip'`, `ELF_SCENES: Array<Scene>`, where
    `Scene = { id, title, needs?, elf: { at: [x, z], place: [x, y, z], level, rotY? }, props: () => THREE.Group[], tidy: (c) => Step[] }`.
    `tidy` returns ordinary job steps; a `use` step that clears a prop calls `c.elf.clear(i)` in its `onDone`.
    Task 2 ships one scene, `looRoll` ("Pip has wrapped the banister in loo roll"): two props, two `use` steps.
  - `binParams` adds `elfScene: pickScene(today(), ELF_SCENES, id => settings ? settings.isOn(id) : true)`.
  - `systems/elf.js` `createElf(ctx) -> { reset(params), clear(i), found(), home(), scene }`:
    `reset` hides the door, the elf and every prop unless `params.holiday` includes `advent`; then shows the door,
    and if `ctx.elfLog.waiting(params.holiday)` puts `items.elf` at the scene's `elf.place` (on the scene's
    floor) and shows that scene's props; otherwise leaves the elf hidden behind his door. `found()` plays the
    existing pick-up sound and toasts `You found ${ELF_NAME}! ${scene.title}`. `home()` hides the elf and calls
    `ctx.elfLog.markFound()`. Props are built once, on first use, and added to their floor's group.

### Task 3: The "Find the elf" job

**Files:**
- Modify: `house/js/holidays.js` (header comment: the `elf` tag), `house/js/settings.js` (add `'elf'` to the
  `christmas` group's `tags`), `house/js/days/days.js` (`tagsFor`, `swapPersonalJobs`), `house/js/jobs/rules.js`,
  `house/js/jobs/jobs.js` (`christmasJobs`), `house/js/jobs/board.js` (`hidden` steps)
- Test: `tests/house/playthrough.mjs`

**Interfaces:**
- Consumes: Task 2 `ctx.elf`, `ctx.elfLog`, `ELF_SCENES`, `ELF_DOOR`, `params.elfScene`.
- Produces:
  - `tagsFor` adds `'elf'` for `girl` and `boy` when `ctx.elfLog.waiting(holiday)` (before `offTags`, like
    `adventDoor`).
  - Rule: `{ id: 'elf', every: 1, must: true, who: ['girl', 'boy'], holiday: 'elf' }`.
  - Job (added in `christmasJobs` when `tags.includes('elf')`; the scene from `params.elfScene`, which
    `christmasJobs` must be passed):
    `{ id: 'elf', title: 'Find the elf', keep: true, steps: [find, ...scene.tidy(c), pick, drop] }` where
    `find = { kind: 'use', hidden: true, level, at: scene.elf.at, label: \`Is that ${ELF_NAME}?\`, onDone: c => c.elf.found() }`,
    `pick = { kind: 'pick', item: 'elf', label: \`Pick ${ELF_NAME} up\` }`,
    `drop = { kind: 'drop', item: 'elf', home: true, label: 'Take him back to his door in the hall', onDone: c => c.elf.home() }`.
    `setup: c => c.elf.reset(c.days.today.params)` (or the equivalent that puts today's scene out).
  - `board.js`: a step with `hidden: true` never shows the floating marker (`updateMarkers`); the action button
    still works when you're close enough.
  - `swapPersonalJobs`: a job with `keep: true` that is still for the new player is left as it is (no
    `board.replace`).
